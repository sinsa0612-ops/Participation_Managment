# 사업비 인건비 배분 관리 웹앱 — 프로젝트 요구사항 정리

> Claude.ai에서 나눈 대화를 Claude Code 고도화 작업을 위해 정리한 문서입니다.

---

## 1. 프로젝트 개요

국비·시비·민간 재원의 사업비 인건비를 여러 연구원에게 자동으로 배분하고 관리하는 웹앱.

- **기준일**: 2026년 5월 18일
- **대상**: 7개 국비 사업, 10명 연구원 (확장 가능)
- **디자인**: 깔끔하고 미니멀한 화이트 베이스

---

## 2. 데이터 구조

### 2-1. 연구원 (Member)

| 필드 | 타입 | 설명 |
|------|------|------|
| id | string | 고유 ID |
| name | string | 이름 |
| employType | "정규직" \| "전문직" \| "위촉직" | 고용형태 |
| rank | "단장" \| "센터장" \| "팀장" \| "연구원" | 직급 |
| salary | number | 월 인건비 (원) |
| maxRate | number | 국비 참여율 상한 (%, 전체 합계 기준, 기본 100) |
| maxProjects | number | 최대 참여 가능 사업 수 (기본 5) |

### 2-2. 사업 (Project)

| 필드 | 타입 | 설명 |
|------|------|------|
| id | string | 고유 ID |
| name | string | 사업명 |
| startDate | string | 사업 시작일 (YYYY-MM-DD) |
| endDate | string | 사업 종료일 (YYYY-MM-DD) |
| yearBudgets | object | 연도별 인건비 예산 (고용형태별 구분) |
| requiredMembers | object | 필수 참여자 (chief: 연구책임자 ID, staff: 실무자 ID 배열) |
| memberConstraints | object | 연구원별 이 사업 한정 참여율 상한 |

**yearBudgets 구조 예시:**
```json
{
  "2025": { "정규직": 30000000, "전문직": 10000000, "위촉직": 5000000 },
  "2026": { "정규직": 20000000, "전문직": 8000000, "위촉직": 3000000 }
}
```

**memberConstraints 구조 예시:**
```json
{
  "memberId_abc": { "maxRate": 30 },
  "memberId_def": { "maxRate": 50 }
}
```

### 2-3. 참여 (Participation)

| 필드 | 타입 | 설명 |
|------|------|------|
| id | string | 고유 ID |
| projectId | string | 사업 ID |
| memberId | string | 연구원 ID |
| role | "연구책임자" \| "실무자" \| "일반참여자" | 역할 |
| startDate | string | 참여 시작일 |
| endDate | string | 참여 종료일 |
| rate | number | 국비 참여율 (%) |

## 3. 핵심 비즈니스 규칙

### 3-1. 참여율 제한

- 연구원의 **국비 참여율 합계**는 `maxRate` 이하여야 함 (동시 참여 시점 기준)
- 사업별로 특정 연구원의 참여율 상한(`memberConstraints`)을 별도 설정 가능
- 실제 적용 상한 = `min(member.maxRate, project.memberConstraints[memberId].maxRate)`
- 참여율은 **천원 단위** 금액으로 역산, 소수점 둘째 자리 오차 허용

### 3-2. 국비 사업 참여 개수 제한

- 한 연구원이 **같은 시점에** 동시 참여할 수 있는 국비 사업은 최대 `maxProjects`개 (기본 5개)
- **단, 현재 기준일로부터 종료까지 6개월 미만** 남은 사업은 참여 개수 카운트에서 제외
  - 카운트 제외 기준: `monthsToEnd(project.endDate) < 6`
  - 단, 인건비 참여율 합산에는 포함됨
- 개수 제한과 참여율 한도를 **동시에** 체크해야 함

**예시:**
> A,B,C,D,E 사업 참여 중인 연구원이 있을 때
> - A 사업이 1~3월에 종료 → 4월부터 A는 카운트 제외 → F 사업 추가 참여 가능
> - B 사업이 9월 종료, 현재 4월 → 6개월 미만 → B 카운트 제외 → G 사업 추가 가능
> - 단, B 사업의 국비 참여율은 계속 합산됨 → 합계 100% 초과 시 추가 참여 불가

### 3-3. 최소 참여율

- 사업에 참여하는 연구원은 **최소 10%** 참여율 배정 필수

### 3-4. 필수 참여자

- 각 사업에는 **연구책임자 1명**, **실무자 1명 이상** 필수 지정
- 자동 배분 시 필수 참여자 우선 배정

### 3-5. 재원 분류

| 재원 | 개인 참여율 합계 제한 | 비고 |
|------|----------------------|------|
| 국비 | 100% 이하 (조정 가능) | 사업 수·참여율 이중 제한 |
| 시비 | 100% 초과 허용 | 제한 없음 |
| 민간 | 100% 초과 허용 | 제한 없음 |

## 4. 자동 배분 알고리즘

### 4-1. 사업 우선순위 정렬

1. **종료일 빠른 순** (오름차순)
2. 종료일이 같을 경우 **총 인건비 예산 큰 순** (내림차순)

### 4-2. 배분 순서

1. 사업을 우선순위 순으로 순회
2. 각 사업에서 **필수 참여자(연구책임자, 실무자) 우선** 배정
3. 나머지 연구원 순서로 예산 소진 방향으로 배정
4. 각 연구원 배정 시 아래 제약 조건 모두 확인:
   - 월별 동시 참여 수 ≤ `maxProjects`
   - 국비 참여율 합계 ≤ `maxRate`
   - 사업 한정 참여율 상한 ≤ `memberConstraints[memberId].maxRate`
   - 최소 참여율 ≥ 10%
5. 예산 기반 참여율 계산 후 **천원 단위** 반올림

### 4-3. 참여율 계산 공식

```
사용 가능한 최대 참여율 = min(member.maxRate - 현재합산율, memberConstraint.maxRate, 월별가용률)
예산 기반 참여율 = min(남은예산 / (월급 × 참여개월), 사용가능최대참여율)
실제 인건비 = floor(월급 × 개월 × 참여율 / 1000) × 1000  // 천원 단위
```

## 6. 고도화 시 추가 개발 필요 사항

### 필수
- [ ] **월별 동시 참여 수 정교화**: 현재는 전체 기간 기준으로 체크하나, 실제로는 월 단위로 슬라이딩하며 체크해야 함
- [ ] **연구원별 참여 기간 개별 설정**: 현재 자동 배분은 사업 전체 기간으로 배정. 연구원마다 참여 시작·종료월을 다르게 설정 가능해야 함
- [ ] **수동 조정 기능**: 자동 배분 결과를 테이블에서 직접 편집 (참여율, 기간 수정)
- [ ] **고용형태별 예산 매칭**: 사업 예산이 정규직/전문직/위촉직으로 구분되어 있으므로, 배분 시 해당 연구원의 고용형태에 맞는 예산에서 차감해야 함

### 선택
- [ ] **CSV / Excel 내보내기**: 배분 결과 다운로드
- [ ] **사업별 배분 결과 요약**: 고용형태별 집행액, 잔액, 집행률
- [ ] **연구원 참여 타임라인 뷰**: 간트 차트 형태로 월별 참여 현황 시각화
- [ ] **데이터 저장**: localStorage 또는 백엔드 연동
- [ ] **유효성 검사 강화**: 필수 참여자 미지정 시 배분 차단, 예산 초과 경고

## 7. 현재 프로토타입 기술 스택

- **프레임워크**: React (hooks 기반)
- **스타일링**: 인라인 CSS
- **상태관리**: useState, useMemo
- **외부 라이브러리**: 없음

## 8. Claude Code 고도화 시작점 제안

```
1. 프로토타입 코드를 Next.js 또는 Vite + React 프로젝트로 이전
2. 데이터 레이어 분리 (store/state 관리 → Zustand 또는 Context API)
3. 자동 배분 알고리즘을 별도 유틸 함수로 분리 (utils/distribute.ts)
4. 월별 슬라이딩 참여 수 체크 로직 고도화
5. 고용형태별 예산 매칭 로직 추가
6. 수동 조정 UI 구현
7. 결과 내보내기 기능 추가
```
